# Quant-firm audit of the Ultra Core XAUUSD project (2026-10-18)

Scope: the repository as it stands (297 tests passing, master 34 commits ahead of origin, unpushed), the research registry, and the live measurement-only demo. Where a claim rests on something I did not see, it is marked **(unverified)**. Nothing here is a profit forecast.

## 0. Central constraint (read this first)
**The bottleneck is not strategies, and it is mostly not engineering. It is that the available information set cannot support a falsifiable edge claim, and the research loop has been spending that scarce information faster than it creates it.**
Evidence in your own project:
- ~645 logged trials, zero survivors, on ~4 years of broker bars (2022-07..2026-10) and 26 years of daily futures. Every trial that looked good was good only in the 2025-26 gold rally (FvgGold claim, #641's VALIDATE, #640).
- The corrected engine overturned the old backtests: M1 vs coarse-M15 A/B moved PF from 1.38 to 0.93. Most "edges" were resolution artefacts, not market structure.
- With ~4 usable years and one regime (a strong bull run since 2024), you cannot distinguish edge from beta: a long-biased rule earns in 2025-26 regardless of skill.
- Selective rules produce 30-60 trades in 4 years (#641: 33, #643: 57). That is statistically unable to confirm even a real PF of 1.3.
What the firm would fix first: **the information set and the decision process** — what data exists that others do not use, and how many looks you allow yourself — before another signal. Concretely: (1) freeze a trial-budget and a single immutable holdout policy; (2) acquire tick-level bid/ask (spread and microstructure are the only places a retail gold trader can plausibly have an informational or cost edge); (3) stop treating the registry as a search engine.

## 2. Data pipeline design (solo-achievable)
- **Layout** (files, no database server): `data/raw/<source>/<symbol>/<kind>/<yyyy>/<mm>/<dd>.parquet` immutable (write-once, chmod read-only, sha256 recorded). `data/canonical/` rebuilt deterministically from raw. `data/features/<feature_set>@<version>/`. `data/manifests/` one JSON per dataset. Use Parquet (columnar, typed) + DuckDB for queries; git-LFS or a simple content-addressed folder for versioning (name = sha256 prefix).
- **Canonical schemas**: `ticks(ts_utc_ns, bid, ask, bid_vol, ask_vol, source_id, ingest_ts)`; `bars(ts_open_utc, tf, o, h, l, c, tick_volume, spread_mean, spread_max, spread_close, n_ticks, source_id)`; `events(event_id, category, scheduled_utc, knowledge_time_utc, actual, consensus, previous, revision_of)`; `fills(order_id, signal_id, ts_signal, ts_send, ts_fill, price_req, price_fill, slippage, retcode, spread_at_send, latency_ms)`.
- **Metadata (every dataset)**: source, server/build, symbol spec (digits, contract, tick value), timezone (UTC only), time of download, first/last timestamp, row count, sha256, gap report, schema version, code commit that produced it.
- **Quality checks (fail the load, not warn)**: monotonic unique timestamps; no bars on closed market; gaps > expected session gap flagged; OHLC consistency; spread ≥ 0 and within the vendor's historical 99.9th percentile; return outliers > 10 sigma list for manual review; cross-source close difference tolerance; holiday calendar check; the "100,000-bar cap" check (count equals cap = truncated download).
- **Point-in-time / knowledge-time**: every row carries `event_time` and `knowledge_time`; a feature at decision time T may use only rows with knowledge_time ≤ T. Indicators on closed bars only; D1/H4 built from lower timeframe with complete-bucket rules (already done in #640/#641). Higher-timeframe values lag by one completed bar by construction and a unit test asserts it (extend `test_asian_london_sim.py`'s truncation test to all features).
- **Revised economic data**: store first release and each revision as separate rows (`revision_of`); backtests read "as known at T". For FOMC/CPI/NFP keep consensus at T-1 day. Without this, no macro-surprise research is valid. ALFRED (FRED vintage) provides vintages for US series; consensus needs a paid or hand-captured source.
- **Feature/dataset versioning**: a feature = (name, definition hash, input dataset hashes, params); stored under that key. Changing code or params creates a new version; old results stay valid because they point at the old key.
- **Reproducible backtest**: `run_manifest.json` = {code commit (refuse dirty), data hashes, config hash, seed, engine version, command line, host, start/end time}. CI rule: any number in a RESULT file must be regenerable by `make reproduce RUN=<id>`.

## 3. Research process (formal)
- **Idea intake**: every idea needs a one-page mechanism memo before any data is touched: who is on the other side of the trade, why do they lose money to you, why would it persist after costs, what would falsify it, expected trade count and power.
- **Worth testing if**: (a) a named counterparty/constraint exists (forced flows, index/ETF rebalances, option expiries, fix windows, LBMA fixes, central-bank behaviour, inventory/liquidity provision, spread/latency asymmetries); (b) required data exists NOW; (c) expected N supports detection (see power); (d) effect size must exceed round-trip cost by ≥2x in the descriptive stage.
- **Pre-registration contents**: hypothesis and mechanism; exact data (hash) and filters; every parameter value; signal, entry, exit, sizing; costs and stress; splits with dates; metrics and thresholds; the number of tests in the family; stopping rule; "what I will do if it fails" (close). Commit before code; commit code before run; commit result after.
- **Splits**: development (tune only here) → validation (frozen rule, one look) → holdout (one look, ever). Never reuse a holdout across hypotheses: the 2026-07..10 window is now burned (read for #640, #641, #643). Create a new holdout by waiting (forward data) rather than by redefining the old one.
- **Walk-forward**: only AFTER a frozen rule passes; anchored expanding window with the SAME frozen rule re-fit by a fixed procedure; it measures stability, never discovers parameters.
- **Statistics**: BH over the family declared in the prereg; DSR with the honest N (all prior trials in the family, plus a discounted weight for others); PBO/CSCV for any parameterised search; minimum detectable effect from sample size: for N trades with per-trade R std ≈ 1, detecting expectancy 0.1R at 5% needs N ≈ 600 (σ²(1.64+0.84)²/0.1² ≈ 620). Therefore low-frequency rules (<150 trades) can falsify but cannot confirm; they need ≥3x as many years or more instruments.
- **Close a line when**: it fails any frozen gate; or power analysis says it cannot be confirmed within 12 months of data; or the effect is smaller than 2x cost.
- **Advance to forward test when**: DEV and VALIDATE pass the frozen gates, the placebo/permutation test is beaten, parameters sit on a plateau (neighbours ≥ 70% of the headline expectancy), cost stress keeps expectancy > 0, BH/DSR clear, and the holdout (fresh) does not contradict. The forward test is 60-90 days frozen on demo with fill telemetry and is an execution/safety gate, not proof.
- **Real money allowed when**: forward test matches the backtest within pre-stated tolerance (expectancy within the backtest's 90% interval, slippage ≤ modelled), no rule violations, operational controls in §6 complete, and size starts at the smallest unit with a loss budget you can lose entirely.

## 4. Verdict on your research families
- **Dead (do not revisit with this data):** generic EMA/trend-pullback rules (#640); Asian-range breakout/continuation and sweep reversal (#641, HYP-070); next-day fade after abnormal moves (#643; 22-year mechanism fails); DXY/yield confirmation of trend (#645; fails on 26 years); ATR-percentile regime buckets (vol governor); scheduled-release direction (event study); FVG/EA31337 clones.
- **Revisit only with better data:** (i) post-release trading with tick bid/ask (needs real spread, depth proxies and consensus/actual); (ii) fix-window/London-fix flows (needs tick data and exact fix times); (iii) execution-cost arbitrage (trading only when spread is anomalously low) — needs historical bid/ask; (iv) cross-asset lead/lag at intraday frequency (needs synchronised intraday DXY/yields, not daily; your earlier DXY H2 test leaked).
- **Never revisit:** anything whose only support is the 2025-26 period; any rule rescued by an added filter after seeing results; martingale/grid/recovery sizing.
- **Most plausible edge for a solo XAUUSD trader:** not directional prediction. Plausible sources are (a) cost/execution edges (do less, trade only when spread/liquidity is favourable, avoid known bad windows), (b) structural calendar flows around fixes, rolls and expiries traded with tiny size, (c) providing a small, risk-capped carry/diversification exposure (long-only exposure to gold is a risk premium, not skill, and should be labelled as such). Expect any real edge to be small (PF 1.1-1.3 gross of nothing) and capacity-limited.
- **Data to test them:** ≥12 months of tick bid/ask with timestamps (capture now), exact London fix and COMEX roll/expiry calendars, first-release macro data with consensus (paid or hand-captured), and a second price source for cross-checks.
- **Credible for a 90-day forward test:** ≥150 trades in DEV+VALIDATE (or an explicit power waiver), PF ≥ 1.25 net and positive in both, positive under 2x cost stress, beating a placebo at p < 0.05, DSR ≥ 0.95 at honest N, no quarter > 40% / trade > 15% of net, parameter plateau, and an economic mechanism written before the test.

## 5. Execution and risk architecture
- **Order lifecycle state machine**: SIGNAL → RISK_CHECKED → SUBMITTED → (ACKED | REJECTED) → (PARTIAL | FILLED) → MANAGED → (CLOSED | CLOSE_FAILED). Every transition is persisted (append-only journal) with a timestamp; restart rebuilds state from broker positions + journal; any position not in the journal = foreign (already handled) or orphan (alert).
- **Pre-trade checks (all fail closed)**: kill-switch file absent; halt latch clear; heartbeat fresh; quote age < 2 s and spread < cap; symbol tradable; account type allowed (demo/real flag matches intent); stop distance ≥ broker minimum and ≤ max; lot within [min, cap]; strategy concurrency (own magics); account exposure (all magics) ≤ cap; daily-loss headroom ≥ worst-case stop loss; news blackout ±30/60 min; margin utilisation < limit; duplicate-signal key unseen; SL/TP sent WITH the order (never added afterwards).
- **Magic scoping / account control**: implemented (own-magic allowlist; foreign positions and pendings block entries; netting accounts refused). Missing: reminders in the external monitor, order-comment tagging checks.
- **Daily loss / drawdown**: define it exactly as the venue does (balance vs equity, day boundary, includes floating). Use internal limits at ≤50% of firm limits (e.g. 1.5% vs 3%). Realized includes commission, swap, fee on every deal (done). Peak-equity trailing drawdown computed from account equity samples at ≥1/min, persisted.
- **Kill switch / halt latch**: STOP file + latch (done). Add: an independent watchdog process that can flatten using a separate MT5 connection if the main process stops sending heartbeats for N minutes **(missing)**.
- **Reconciliation**: nightly job: journal vs broker deals; any difference > $0.01 or any unknown deal raises a halt latch. Weekly: engine replay vs broker fills, split into Ultra Core and foreign.
- **Slippage/fill quality**: log requested vs filled price, spread at send, latency, retcode; rolling slippage and reject-rate alarms; auto-reduce size or halt when the 20-fill mean slippage exceeds 2x the model.
- **Alerting / incident response**: severity levels, a single on-call channel, external dead-man (healthchecks.io-style), a runbook entry per alert, and a post-incident note appended to a log. Practise: kill the process, pull the network, sleep the PC, reboot, and confirm each produces the documented outcome.
- **What is safe for a measurement-only demo (today)**: current state, provided you accept that nothing alerts you if the PC sleeps and that no order-path code is exercised.
- **Required before live personal capital**: external dead-man alert; tested crash/sleep/network/reboot recovery; independent flatten watchdog; order journal + reconciliation; fill-quality telemetry from ≥100 demo fills with a live-parity strategy; secrets rotated; account is real-flag verified; a written loss budget; position size at the broker minimum.
- **Required before a funded prop account**: all of the above plus written firm confirmation of every rule (§6), the firm's exact daily-loss and drawdown formulas implemented and unit-tested with their numbers, internal limits at ≤50% of firm limits, a platform-restriction check (no prohibited behaviours: news, minimum hold, consistency), a 90-day frozen forward test with an edge worth paying for, and an evaluation-fee budget treated as spent.

Tests: reproduce one old result byte-for-byte from its manifest. Done when: any RESULT file has a manifest and can be regenerated. Do NOT: start a new strategy.

Deliverables: tick/bid-ask recorder on the demo connection writing daily Parquet with validation; gap/outlier report; external heartbeat set up (2 minutes at healthchecks.io). Tests: each drill documented with the observed outcome. Done when: ≥200 demo fills logged and the engine's cost model is calibrated to them. Do NOT: judge profitability from the probe.
- **Week 9-12 — one hypothesis, properly.** Goal: at most TWO pre-registered hypotheses that pass the §3 intake (mechanism memo, data available, adequate power). Deliverables: mechanism memos, preregs, frozen code, one run each on a fresh holdout (forward data accrued since week 3). Tests: placebo, cost stress, plateau. Done when: each is closed or promoted to a 90-day frozen forward test. Do NOT: run more than two trials, and do NOT touch the burned 2026-07..10 holdout.

## 8. Final verdict
**Honest assessment:** this is a well-instrumented research lab around a market where you have not found, and with current data probably cannot find, a durable edge. The engineering has become genuinely good (fail-closed scoping, latches, tests, honest negative results); the failure is informational, not technical. The product today is the discipline and the infrastructure, not a strategy. Funding anything on the strength of the current evidence would be paying for a lottery ticket.
